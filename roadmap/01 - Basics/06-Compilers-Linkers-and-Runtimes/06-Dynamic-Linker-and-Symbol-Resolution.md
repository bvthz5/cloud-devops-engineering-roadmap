# 06 — Dynamic Linker and Symbol Resolution

When a Linux process starts, the kernel loads the ELF executable and hands control over to the **Dynamic Linker** (`ld-linux.so`) before your application's `main()` function ever runs!

---

## 1. Dynamic Library Search Order

The dynamic linker searches for shared libraries in this exact priority order:
1. Paths specified in the binary's **`DT_RPATH`** ELF attribute (deprecated).
2. Paths listed in the **`LD_LIBRARY_PATH`** environment variable.
3. Paths specified in the binary's **`DT_RUNPATH`** ELF attribute.
4. Cached entries in `/etc/ld.so.cache` (generated by running `sudo ldconfig`).
5. Default trusted system directories: `/lib/` and `/usr/lib/` (or `/usr/lib64/`).

---

## 2. The Power of `LD_PRELOAD`

`LD_PRELOAD` is an environment variable that forces the dynamic linker to load custom shared libraries **before any other library**, including `libc`.
- **Performance Profiling:** Used by tools like Google Perftools (`libtcmalloc.so`) or Jemalloc (`libjemalloc.so`) to replace standard `malloc()` with high-speed allocators.
- **Security Sandboxing / Auditing:** Intercepts sensitive system calls (like `connect()` or `execve()`).

```bash
# Example: Run application using high-performance jemalloc allocator
LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libjemalloc.so ./my_database_server
```
