# 04 - Memory Management & Virtual Memory

Memory management is one of the most sophisticated responsibilities of an operating system. It coordinates physical RAM, CPU caches, and virtual address spaces to ensure programs execute efficiently and securely.

## 2. Logical vs. Physical Address Space

In early computing, programs referenced physical memory addresses directly. If Program A wrote to address `0x0040`, it overwrote physical RAM cell `0x0040`, making multitasking impossible.

Modern operating systems decouple memory via **Virtual Memory**:

```
Process A Virtual Address Space:       Physical RAM (DRAM Frames):
┌─────────────────────────────┐        ┌─────────────────────────────┐
│ Page 0 (0x0000 - 0x0FFF)    ├───────►│ Frame 12 (0xC000 - 0xCFFF)  │
│ Page 1 (0x1000 - 0x1FFF)    ├─┐      ├─────────────────────────────┤
└─────────────────────────────┘ │  ┌──►│ Frame 45 (0x2D00 - 0x2DFF)  │
                                │  │   ├─────────────────────────────┤
Process B Virtual Address Space:│  │   │ Frame 89 (0x5900 - 0x59FF)  │
┌─────────────────────────────┐ │  │   └─────────────────────────────┘
│ Page 0 (0x0000 - 0x0FFF)    ├─┼──┘   ▲
│ Page 1 (0x1000 - 0x1FFF)    ├─┘      │ Address Translation via
└─────────────────────────────┘        │ Hardware MMU & Page Table
```

- **Logical (Virtual) Address:** An address generated by the CPU from the perspective of a running process (typically a 64-bit flat address space).
- **Physical Address:** The actual hardware electrical address loaded onto the DRAM memory bus.
- **MMU (Memory Management Unit):** The hardware component on the CPU that performs the real-time translation of virtual addresses into physical addresses using **Page Tables**.

---

## 3. Paging Architecture

- **Page:** A fixed-size contiguous block of virtual memory (standard size is **4 KB**; HugePages can be 2 MB or 1 GB).
- **Frame:** A fixed-size block of physical RAM matching the page size.
- **Page Table:** A data structure maintained by the OS kernel for each process that maps virtual Page Numbers (VPN) to physical Page Frame Numbers (PFN).

### The Translation Lookaside Buffer (TLB)
Because looking up page tables in RAM for every single memory access would cut CPU speed in half, CPUs feature a specialized high-speed hardware cache called the **TLB (Translation Lookaside Buffer)**.
- **TLB Hit:** Physical address is cached; translation takes < 1 nanosecond.
- **TLB Miss:** CPU walks the multi-level page table in RAM, loads the mapping into the TLB, and resumes.

## 4. Virtual Memory & Page Fault Handling

Modern systems use **Demand Paging**: pages are not loaded into physical RAM until the program actually attempts to access them.

### What Happens During a Page Fault?
1. The CPU accesses a virtual address whose page table entry has the **Present bit = 0**.
2. The MMU raises a hardware interrupt: **Page Fault Exception**.
3. The CPU halts the process and switches to the kernel's page fault handler in Ring 0.
4. The kernel checks:
   - Is the address invalid/unmapped? ➔ Send **`SIGSEGV` (Segmentation Fault)** and terminate the process.
   - Is the address valid but on disk (in swap or a file)? ➔ Allocate a free physical frame in RAM.
5. The kernel issues a disk I/O request to load the page into RAM.
6. The process is placed in sleep state while I/O completes.
7. Once loaded, the kernel updates the page table (Present bit = 1) and instructs the CPU to **restart the exact instruction** that faulted!

## 5. Page Replacement Algorithms & Thrashing

When physical RAM is 100% full and a new page must be allocated, the OS must choose an existing page to evict to Swap.

| Algorithm | Mechanism | Practical Reality |
|---|---|---|
| **FIFO (First-In, First-Out)** | Evicts oldest loaded page. | Simple, but suffers from *Belady's Anomaly* (adding RAM can increase page faults!). |
| **Optimal (OPT / MIN)** | Evicts page that will not be used for longest future time. | Theoretical benchmark; impossible to implement without clairvoyance. |
| **LRU (Least Recently Used)** | Evicts page that has gone unused for longest past duration. | Gold standard heuristic; approximated in Linux via active/inactive lists and Clock algorithms. |

### Thrashing: The Performance Death Spiral
**Thrashing** occurs when a computer's physical memory is so oversubscribed that the operating system spends more CPU cycles swapping pages in and out of disk than executing user instructions.
- Symptoms: CPU utilization plunges, Disk I/O wait (`%wa`) hits 100%, and system becomes completely unresponsive.
- Solution: Terminate memory-hungry processes, add physical RAM, or tune `vm.swappiness`.
